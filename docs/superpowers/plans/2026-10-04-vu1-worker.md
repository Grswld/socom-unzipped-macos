# VU1 on its Own Core Implementation Plan — Part 1 (Task 0: the overlap measurement)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure, in a live mission, how much of the inline VU1/VIF1/GS work could overlap with the game's other guest threads, and how the VIF1 i-bit interrupt sits in the frame, so the worker design (spec 3.5) is confirmed or revised before code is written.

**Architecture:** A read-only Dev instrument: a pure statistics window (`runtime/vu1_overlap_stats.h`) fed from three existing sites (the VIF1 loop of `PS2Memory::processPendingTransfers`, the i-bit in the VIF1 interpreter, the STC write) and a probe the runtime installs (ready guest threads other than the current one, from `EeScheduler::thread(id)`). One line a second under `PS2X_VU1_OVERLAP_TRACE`.

**Tech Stack:** C++20, MiniTest (`ps2x_tests`), the knob registry (`knobs.h`, `tools_py.knobs`), macOS `sample` not needed.

**Spec:** `docs/superpowers/specs/2026-10-04-vu1-worker-design.md` (sections 3.5 and 5, the Task 0 gate).

**Why the plan is in two parts:** the spec makes the i-bit measurement a gate that can revise the design. Part 2 (the queue, the recording rig, the worker, the sync points, the clock, the gates) is written after Task 0's findings, against the design they confirm.

## Review Focus

1. **The probe while no game is running** (ps2x_tests, boot): no scheduler or no threads yet — expected `readyOthers = -1` and no crash. Pinned by Task 0a's `a probe-less window still counts`.
2. **An STC with no i-bit before it** (the game writes FBRST.STC at boot or on reset): expected no latency sample, no underflow. Pinned by Task 0a's `an STC without an i-bit records no latency`.
3. **A second i-bit before the STC** (two stalls queued): expected the latency measured from the most recent i-bit. Pinned by Task 0a's `the latest i-bit starts the latency`.
4. **A window spanning less than a second at shutdown**: no division by zero. Pinned by Task 0a's `report over a zero-length window`.
5. **Thread ids outside the probe's scan range**: a Ready thread the scan skips would be missed. Expected the probe to cover every id the scheduler hands out. Pinned by Task 0b Step 1: the scan's bound is `EeScheduler::kLastThreadId` itself.

```cpp
#pragma once
// macOS fork, the VU1 worker's Task 0 (docs/superpowers/specs/2026-10-04-vu1-worker-design.md, 3.5 and 5).
// Read-only: how much of the inline VIF1/VU1/GS work ran while another guest thread was ready (the time a worker on
// its own core could overlap), and how the VIF1 i-bit interrupt and its FBRST.STC resume sit in the frame.
// Pure: the window and its report. vu1_overlap_stats.cpp holds the process-wide window, the knob and the probe.
#include <cstdint>
#include <cstdio>
#include <map>
#include <string>

namespace vu1overlap
{
    // What the scheduler says when a VIF1 kick is processed: guest threads in Ready other than the current one
    // (-1: no scheduler), and the current guest thread's id (-1: none).
    struct Probe
    {
        int readyOthers = -1;
        int currentTid = -1;
    };

    struct Window
    {
        uint64_t vif1Ns = 0;            // host time inside processPendingTransfers' VIF1 loop (VU1 and GS inline)
        uint64_t overlappableNs = 0;    // the part of it that ran while another guest thread was Ready
        uint64_t kicks = 0;
        std::map<int, uint64_t> kicksByTid;
        uint64_t ibits = 0, stcs = 0;
        uint64_t stcLatencyNsTotal = 0, stcLatencyNsMax = 0, stcLatencySamples = 0;
        uint64_t lastIbitNs = 0;
        bool ibitOpen = false;

        void addVif1(uint64_t ns, const Probe &p)
        {
            vif1Ns += ns;
            ++kicks;
            if (p.readyOthers > 0)
                overlappableNs += ns;
            if (p.currentTid >= 0)
                ++kicksByTid[p.currentTid];
        }
        void noteIbit(uint64_t nowNs)
        {
            ++ibits;
            lastIbitNs = nowNs;
            ibitOpen = true;
        }
        void noteStc(uint64_t nowNs)
        {
            ++stcs;
            if (!ibitOpen)
                return;
            ibitOpen = false;
            const uint64_t d = nowNs >= lastIbitNs ? nowNs - lastIbitNs : 0u;
            stcLatencyNsTotal += d;
            stcLatencyNsMax = d > stcLatencyNsMax ? d : stcLatencyNsMax;
            ++stcLatencySamples;
        }

        std::string report(double seconds) const
        {
            const double s = seconds > 0.0 ? seconds : 1.0;
            const double vif1 = double(vif1Ns) / 1e6 / s, over = double(overlappableNs) / 1e6 / s;
            const double pct = vif1Ns ? 100.0 * double(overlappableNs) / double(vif1Ns) : 0.0;
            const double mean = stcLatencySamples ? double(stcLatencyNsTotal) / double(stcLatencySamples) / 1e6 : 0.0;
            char buf[256];
            std::snprintf(buf, sizeof buf,
                          "[vu1-overlap] vif1=%.0f ms/s overlappable=%.0f ms/s (%.0f%%) kicks=%.0f/s ibits=%.1f/s "
                          "stc=%.1f/s stc_latency mean=%.2f max=%.2f ms by_tid=",
                          vif1, over, pct, double(kicks) / s, double(ibits) / s, double(stcs) / s, mean,
                          double(stcLatencyNsMax) / 1e6);
            std::string line(buf);
            bool first = true;
            for (const auto &[tid, n] : kicksByTid)
            {
                line += (first ? "" : ",") + std::to_string(tid) + ":" + std::to_string(n);
                first = false;
            }
            return line;
        }
    };
}
```

// macOS fork, the VU1 worker's Task 0: the process-wide overlap window behind PS2X_VU1_OVERLAP_TRACE.
#include "runtime/vu1_overlap_stats.h"
#include "ps2x/knobs.h"

#include <chrono>
#include <cstdio>

namespace vu1overlap
{
    namespace
    {
        Window g_window;
        uint64_t g_windowStartNs = 0;
        ProbeFn g_probe = nullptr;
        void *g_probeCtx = nullptr;
    }

    bool on()
    {
        static const bool s_on = ps2x::knob("PS2X_VU1_OVERLAP_TRACE") != nullptr;
        return s_on;
    }
    void setProbe(ProbeFn fn, void *ctx)
    {
        g_probe = fn;
        g_probeCtx = ctx;
    }
    Probe probe() { return g_probe ? g_probe(g_probeCtx) : Probe{}; }
    uint64_t nowNs()
    {
        return uint64_t(std::chrono::duration_cast<std::chrono::nanoseconds>(
                            std::chrono::steady_clock::now().time_since_epoch()).count());
    }
    void addVif1(uint64_t ns, const Probe &p)
    {
        if (!on())
            return;
        g_window.addVif1(ns, p);
        const uint64_t now = nowNs();
        if (g_windowStartNs == 0)
            g_windowStartNs = now;
        if (now - g_windowStartNs >= 1'000'000'000ull)
        {
            std::fprintf(stderr, "%s\n", g_window.report(double(now - g_windowStartNs) / 1e9).c_str());
            g_window = Window{};
            g_windowStartNs = now;
        }
    }
    void ibit()
    {
        if (on())
            g_window.noteIbit(nowNs());
    }
    void stc()
    {
        if (on())
            g_window.noteStc(nowNs());
    }
}

# Part 2 — the worker (written 2026-10-04 against research/84: CONFIRMED)

**Goal:** VIF1, VU1 and the GS front end run on a worker core, fed by one ordered queue, with about four drains a game
frame, behind `PS2X_VU1_THREAD` (default 0 until the gates pass).

**Findings Part 2 rests on** (research/84 and the code read while planning):
- All VIF1 kicks come from guest thread 1; a kick is processed at once inside the CHCR store
  (`writeIORegister` → `processPendingTransfers`, `ps2_memory.cpp` ~1688). Some stubs free the packet right after
  (`GS.cpp` ~675: `guestFree(pktAddr)`), so data is copied at post time. Chain kicks already gather `chainData` at the
  kick (`ps2_memory.cpp` ~1560-1671); normal-mode kicks are read from RAM later and must be copied at post.
- `processPendingTransfers` runs GIF (PATH3) transfers, then VIF0, then VIF1, then `m_gifArbiter->drain()`. VIF0 feeds
  VU0 (the EE's macro unit) and stays inline; it has no GS path, so posting GIF before it and VIF1 after it keeps the
  GS order.
- DMA-1 completion (CHCR STR, QWC, D_STAT CIS) is decided on the game thread from the MFIFO ring state, not from VU1's
  results (`ps2_memory.cpp` ~1957-1962): kicks keep completing at once.
- The real waits: VIF1 registers (1.7/frame), D_STAT (1.7), GIF registers (0.9); GS privileged reads and EE access to
  VU1 memory: 0 in every second of two sessions, boot included.
- `PS2Memory::queueIntcCause` is mutex-protected: the worker may raise INTC5 at an i-bit.
- The MSCAL/MSCNT callbacks (`ps2_runtime.cpp` ~733-800) read the current EE context's `vu0_fbrst` (D/T enables) and
  write its `vu0_vpu_stat` (D/T stop bits): EE state the worker must not touch.
- VU1 adds its host time to `ps2GuestClockExcludedNs` (`ps2_vu1_core.cpp` ~2998); on the worker it must not.
- `EeScheduler` calls `gs().guestFrameBoundary()` at every VBlank on the game thread (`EeScheduler.cpp` ~2224): the GL
  backend's producer-side frame mark, which must stay in order with the GS commands.
- The native GIF fast paths (`tryProcessNativeGifImageUploadChain`, `tryProcessNativeGifPackedChain`) feed the GS
  directly; upstream's tests assert they match the generic path's output (`ps2_memory_tests.cpp` ~1388, ~1465).

**Global Constraints (Part 2, in addition to Part 1's):**
- Headers the generated code includes may now change where a task says so (`ps2_memory.h` is not touched; the plan's
  executor uses public `PS2Memory`/`GS` API only). A rebuild of the generated code is the cost when one does.
- `PS2X_VU1_THREAD=0` is byte-identical to today: every guard is `if (vu1domain::shouldPost()) { ...; return; }` with
  `shouldPost()` false when the worker is off, and no other behaviour change.
- The worker is the only thread that runs VIF1, VU1, the GIF arbiter and the GS front end while it is on.
- Every drain and every backpressure wait is added to `ps2GuestClockExcludedNs` (spec 3.4).

**Review Focus (Part 2):**
1. **In-process restart (Sprint 17 Q2) and shutdown with work queued**: the worker must drain, stop and restart around
   the runtime's reset, never apply an item to a reset memory. Task 6's `stop drains before it returns`.
2. **A VIF1 i-bit stall while the queue holds the STC behind PATH3 work**: the stalled bytes resume only at the STC
   item, in order. Task 4's replay of a recorded i-bit frame, and Task 2's `items apply in order across a stall`.
3. **A game-thread read of a VIF1 register while the worker is mid-item**: it must see the state after all posted items.
   Task 5's `a VIF1 register read drains first`.
4. **Normal-mode kicks whose source memory is freed right after the kick**: the item must own a copy. Task 3's
   `a posted normal-mode transfer owns its bytes`.
5. **D/T stop bits set by a VU1 program on the worker**: never written into the live EE context from the worker. Task 6's
   counter, and the `vu0_vpu_stat` merge at drain.

### Task 1: The work queue (pure, thread-safe)

**Produces** (namespace `vu1work`, `runtime/vu1_work_queue.h`):
```cpp
enum class Kind : uint8_t { Vif1Data, GifPath3, ArbiterDrain, Vif1Reg, GsPriv32, GsPriv64, GsReg, ClearFb,
                            GuestFrameBoundary, FrameMark };
struct WorkItem { Kind kind = Kind::FrameMark; uint32_t a = 0; uint64_t b = 0; std::vector<uint8_t> bytes; };
class WorkQueue {
public:
    uint64_t push(WorkItem &&item);                 // producer; returns the item's sequence (1, 2, ...)
    bool pop(WorkItem &out, uint64_t &seq);         // consumer; blocks; false once closed and empty
    void markDone(uint64_t seq, bool frameMark);    // consumer: item `seq` fully applied
    void waitDone(uint64_t seq);                    // producer: until markDone(>= seq) or closed
    uint64_t lastPushed() const;
    void waitFramesAhead(unsigned limit);           // producer: while pushedFrames - doneFrames > limit
    unsigned framesAhead() const;
    void close();
};
void serialize(const WorkItem &item, std::vector<uint8_t> &out);          // kind u8, a u32, b u64, n u32, bytes
bool deserialize(const uint8_t *&p, const uint8_t *end, WorkItem &item);
```

### Task 3.1: The queue as a lock-free SPSC ring with a preallocated arena
`runtime/vu1_spsc_ring.h`: one producer (game thread), one consumer (worker). Fixed slot array (power of two) of
`{kind, a, b, payload offset/size, payload end}`; payload bytes copied once into a preallocated byte arena (64 MB, wraps
by skipping the tail; a payload over half the arena falls back to a heap block owned by its slot). Items are invisible
until `publish()`; `post` publishes when the worker is asleep or every 64 items, and `flush()` publishes at batch ends
(end of `processPendingTransfers`, before any drain, at the frame boundary, at stop). The worker sleeps on the published
index with `std::atomic::wait` behind a `sleeping` flag (seq_cst on both sides: no lost wake-up); the producer waits on
`done`/`frames done` the same way, notified only when it is waiting. The consumer reads payloads in place (`ItemView`)
and releases slot and arena in order. Tests: order and payload integrity across threads (1M items, checksums), invisible
until publish, waitDone, frames ahead, close wakes both sides, a full ring and a full arena block then continue, arena
wrap with mixed sizes, an oversize payload, a no-lost-wake-up stress (bursts with sleeps).
The domain, executor, recorder and replay tool switch to `ItemView`; `WorkItem` stays the record format.

### Task 3.2: The frames-ahead bound and input-to-display latency
Sample frames-ahead after the backpressure wait as well as before; the bound is "<= queueFrames after the wait".
Latency: the time of each game frame's first pad read (`scePad2Read`) is kept by frame index; the index of the last
completed frame is the game thread's at sceGsSyncV (worker off) or the last FrameMark the worker applied (worker on);
at every host present (after `EndDrawing`) latency = now - pad time of the completed frame. p50/p95 in the stats line,
worker on and off.

### Task 3.3: Slow frames tagged
A game frame over 33.4 ms is tagged `worker` (a backpressure wait > 0.5 ms in it), `readback` (a GL render-target or
VRAM readback in it: a counter the GL backend increments), both, or `game` (neither). Counts per window.

### Task 3.4: The guest allocator, O(log n) with the same first-fit addresses
Address-ordered free blocks with the same first-fit choice (lowest address that fits with its alignment), so every
address returned is the one today's code returns: a differential test against the current implementation on 100,000
random alloc/free sequences.

### Task 3.5: The VU rounding scope writes FPCR only when it changes
`VuRoundingScope` skips the set/restore when the thread already rounds toward zero (the game thread does since boot; the
worker sets it once at start). Bit-identical by construction; VU1 goldens and the replay gate confirm.

0 foreign, 0 i-bit mismatches).
